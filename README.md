## 2. 程式用途與 Colab 執行說明

### 程式用途
本程式用於自動整理「桌遊體驗」（每人 120 元）與「電影欣賞」（每人 80 元）兩場活動的原始文字報名名單。透過 Python 字串方法與容器型別（`tuple`、`list`、`set`、`dict`）的搭配操作，依序完成：
1. **文字清理**：去除多餘半形空白、統一轉為小寫並依逗號拆分為串列。
2. **去重與名單比對**：利用集合（`set`）去除同場重複報名，並透過交集、聯集與差集計算共同參加者、全部參加者及單場參加者名單。
3. **排序與費用計算**：依英文字母順序排序名單、以切片取得通知名單前兩位，最後透過字典（`dict`）彙整人數與各場／總應收金額並以 f-string 格式化輸出摘要。

## 4. 個人回答

### 問題一：測試一中，整理後的桌遊串列有 4 筆資料，為什麼桌遊費用應以 3 人計算？直接把字串拆成 list，和再轉成 set，各自保留了什麼、失去了什麼？
> **回答**：
> 1. **為什麼以 3 人計算費用**：在測試一的整理串列 `['amy', 'ben', 'amy', 'cora']` 中，`"amy"` 出現了兩次（來自原始資料的 `" Amy"` 與 `" amy"`，經統一轉小寫與去空白後判定為同一人）。根據活動規則，同一個人在同一場活動重複報名只算一位參加者、也只收一次費用，因此實際有效參加人數為 `amy`、`ben`、`cora` 共 **3 人**，應收費用為 $3 \times 120 = 360$ 元。
> 2. **`list` 與 `set` 的差異比較**：
>    - **直接把字串拆成 `list`**：
>      - **保留了**：原始報名的**先後順序**（索引位置），以及**所有重複出現的項目**（可看出誰重複報名了幾次）。
>      - **失去了**：無法直接判斷實際不重複的人數，也無法直接進行交集、聯集、差集等名單比對運算。
>    - **再轉成 `set`**：
>      - **保留了**：該場活動所有**不重複的唯一參加者**，並獲得高效的**集合運算能力**（`&`、`|`、`-`）。
>      - **失去了**：原本報名的**先後順序**（集合是無序的，不支援索引取值）以及**每個人重複報名的次數資訊**。

### 問題二：測試三中，兩場活動只有 3 位不同的人，為什麼是 6 人次、總應收仍是 600 元？請用集合關係與算式說明。
> **回答**：
> 1. **集合關係說明**：
>    - 測試三整理並去重後，桌遊集合 $A = \{\text{'amy'}, \text{'ben'}, \text{'cora'}\}$，電影集合 $B = \{\text{'amy'}, \text{'ben'}, \text{'cora'}\}$，兩者為**完全相等的集合**（$A = B$）。
>    - 因此，兩場的**聯集**（總不重複人數）為 $|A \cup B| = |A| = |B| = 3$ 人；**交集**（共同參加者）為 $|A \cap B| = 3$ 人；兩個**差集**（只參加單場者）皆為空集合（$|A - B| = 0$，$|B - A| = 0$）。
> 2. **算式說明**：
>    - **報名人次**：依據規則，報名人次是兩場活動各自去重後的人數相加（參加兩場者算兩人次）。即 $|A| + |B| = 3 + 3 = 6$ 人次（也可透過排容原理驗證：$|A \cup B| + |A \cap B| = 3 + 3 = 6$ 人次）。
>    - **總應收金額**：兩場活動費用分別計算，這 3 位參加者同時報名了兩場活動，因此兩場皆須收費：
>      $$\text{總應收} = (|A| \times 120) + (|B| \times 80) = (3 \times 120) + (3 \times 80) = 360 + 240 = 600\text{ 元}$$
